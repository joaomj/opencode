---
description: Find and prioritize evidence-based project improvement and feature opportunities
---

Use the `project-opportunities` workflow for `$ARGUMENTS`.

1. Reconstruct the current project state from repository evidence before making recommendations.
2. Separate completed work, unfinished work, stated intentions, and speculation.
3. Return only three to five credible opportunities, ranked by value, evidence, effort, risk, and dependencies.
4. Recommend one next opportunity and explain why it comes first.
5. Keep the work read-only. Do not create a plan, ticket, branch, code change, commit, or pull request.
6. Offer a focused exploration or implementation-planning handoff only after the opportunity assessment.
